Créer des outils KTRX

Du poste vierge au premier outil publié. Une fois la machine prête (étapes 1 à 3, 10 minutes), on ne fait plus que l'étape 4.

1Installer Rust

Les outils sont écrits en Rust et compilés en WebAssembly. À faire une seule fois par machine.

macOS · Linux 
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
Windows (PowerShell) 
winget install Rustlang.Rustup

Sous Windows, rustup propose d'installer les « Visual Studio Build Tools » : accepte. Ensuite, ferme et rouvre le terminal, puis ajoute la cible WebAssembly :

rustup target add wasm32-wasip2

2Installer ktrx-dev

ktrx-dev est l'outil de l'équipe : il crée, vérifie et publie. Il s'installe sans droits administrateur.

macOS · Linux 
curl -fsSL https://ktrx-site.tiagoantunes2009.workers.dev/install-dev.sh | sh
Windows (PowerShell) 
irm https://ktrx-site.tiagoantunes2009.workers.dev/install-dev.ps1 | iex

Ouvre un nouveau terminal (ou ajoute ~/.ktrx/bin au PATH), puis vérifie :

ktrx-dev --version
ktrx-dev doctor --fix

doctor contrôle tout et dit quoi corriger. Il doit finir par « Tout est prêt ». Le mot de passe n'est pas demandé à ce stade.

3Se connecter (pour publier)

Un seul mot de passe pour toute l'équipe, nécessaire uniquement pour publier. Créer et tester un outil n'en demande aucun.

ktrx-dev login

Saisie masquée. Le mot de passe est celui de l'équipe (il n'est écrit nulle part ici : demande-le à un membre de l'équipe).

Il est stocké sur la machine (~/.config/ktrx/dev.toml, %APPDATA%\ktrx\dev.toml sous Windows). Ne le mets jamais dans un fichier du projet ni dans un commit. Pour le changer : npx wrangler secret put ADMIN_PASSWORD dans site/.

4Créer un outil avec une IA

Ouvre un dossier vide, lance Claude Code (ou une autre IA de code) dedans, et colle l'un des prompts. Remplace uniquement ce qui est entre <…>.

Prompt 0 — préparer une IA (à faire une fois par machine)

Lis ce guide et applique la partie 1 (installation), sans créer d'outil : https://ktrx-site.tiagoantunes2009.workers.dev/dev/guide-ia.md

L'IA installe tout, vérifie, puis attend. Ensuite, tes prompts « crée-moi tel outil » suffisent : elle ne te demande que le mot de passe, au moment de publier. Les prompts A, B et C ci-dessous sont l'équivalent autonome, si l'IA n'a pas accès au lien.

Prompt A — à partir d'une idée

Tu vas créer un outil pour KTRX.
1. Si `ktrx-dev --version` échoue, installe-le : macOS/Linux `curl -fsSL https://ktrx-site.tiagoantunes2009.workers.dev/install-dev.sh | sh`, Windows `irm https://ktrx-site.tiagoantunes2009.workers.dev/install-dev.ps1 | iex`. Lance ensuite `ktrx-dev doctor --fix` et corrige ce qu'il signale.
2. Lis le guide complet : `ktrx-dev guide` (au minimum les sections 3 à 12).
3. Lance `ktrx-dev init`, puis crée l'outil : <ce qu'il doit faire>.
   Commande : `ktrx-dev new <NOM-MYTHOLOGIQUE-EN-MAJUSCULES> <Nom-Lisible> --category <investigation|analysis|encoding|generation>`.
4. Remplace TOUS les « À COMPLÉTER » et « À REMPLACER » (src/lib.rs avec des tests sans Internet, manifest.toml, README.md).
5. `ktrx-dev check <nom>` doit finir par « Tout est bon ». Ne contourne aucun contrôle.
6. Seulement alors, DEMANDE-MOI le mot de passe de publication, enregistre-le avec `ktrx-dev login --password <mot de passe>` (ne l'écris dans aucun fichier), puis `ktrx-dev publish <nom>` et donne-moi l'adresse de la page.
Règles : un outil = une fonction. Pas de Git ni GitHub. Aucun accès réseau ou fichier hors des primitives du moteur (guide, section 9).

Prompt B — à partir d'une documentation en ligne

Tu vas créer un outil KTRX à partir de cette documentation : <URL>.
Lis-la, puis fais l'outil qui <fonction précise, ex. interroger tel endpoint et résumer la réponse>.
Suis exactement la procédure ci-dessus (installation de ktrx-dev si besoin, `ktrx-dev guide`, `ktrx-dev init`, `ktrx-dev new`, `ktrx-dev check` jusqu'à « Tout est bon »). Demande-moi le mot de passe seulement au moment de publier, enregistre-le avec `ktrx-dev login --password …`, puis `ktrx-dev publish`.

Prompt C — modifier un outil existant

Modifie l'outil KTRX « <nom> » : <changement voulu>.
`ktrx-dev get <nom>` récupère les sources. Incrémente `version` dans manifest.toml ET Cargo.toml. Mets à jour le README si besoin. `ktrx-dev check <nom>` jusqu'à « Tout est bon ». Demande-moi le mot de passe, `ktrx-dev login --password …`, puis `ktrx-dev publish <nom>`.

5À la main, sans IA

ktrx-dev new neith JSON-Inspector --category analysis
# remplir src/lib.rs, manifest.toml, README.md (chaque « À COMPLÉTER »)
ktrx-dev check neith       # tests, compilation, exemples exécutés, règles de doc
ktrx-dev publish neith     # refait check, puis publie

L'outil est visible tout de suite sur le site et s'installe avec ktrx install neith.

6Les règles à ne pas rater

  • Nom : mythologique, en majuscules A–Z, unique. ktrx-dev new refuse un nom déjà pris.
  • Une version publiée ne change jamais. Toute modification = nouvelle version dans manifest.toml et Cargo.toml.
  • Un outil = une fonction. Aucune logique d'outil dans le moteur.
  • Permissions : seulement celles nécessaires (network, file-read, file-write, raw-net, process). Jamais de liste d'hôtes dans le manifeste.
  • Erreurs : renvoyer {"error":"…"}, jamais de panic sur une entrée utilisateur.
  • README : sans image ni HTML ; l'emblème icon.png (1024×1024, sans texte) est facultatif, un défaut est fourni.
  • Pas de Git : tout passe par le registre.

CommandeRôle
